# Communication Rules — 沟通规范

## 核心原则

所有面向项目负责人的沟通，必须以简体中文为主。代码、文件名、终端命令保持英文。

## 语言规则

**必须用中文：** 实现计划、架构解释、风险分析、决策依据、阶段总结、错误分析、对用户问题的回答。

**可以保持英文：** 代码、文件名、终端命令、数据库字段名、环境变量名。

## 术语注释规范

凡在中文说明中出现英文缩写，必须立即在括号内附上中文解释：

| 英文 | 中文 |
|---|---|
| MVP | 最小可行产品 |
| API | 应用程序接口 |
| RLS | 行级安全策略 |
| i18n | 国际化 |
| SEO | 搜索引擎优化 |
| PWA | 渐进式网页应用 |
| Auth | 身份认证 |
| OAuth | 开放授权协议 |
| GDPR | 欧盟通用数据保护条例 |
| SSR | 服务端渲染 |
| CI/CD | 持续集成/持续部署 |

如遇上表未列出的缩写，同样需要附加中文解释。

## 禁止行为

- 禁止输出仅有英文的大段说明性内容
- 禁止在未附中文注释的情况下堆砌英文缩写
